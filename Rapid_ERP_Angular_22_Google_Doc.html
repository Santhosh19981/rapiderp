Any code submitted by any team member or contractor that violates these standards will NOT be received or merged into the codebase. Every Pull Request must achieve a perfect 10/10 (100%) score against the Code Review Scorecard.

1. Standard 1: Modern Angular 22 Architecture & Signals Paradigm

  • Standalone Components by Default: All components, pipes, and directives must use standalone: true. NgModules are completely deprecated and prohibited in new code.
  • Mandatory ChangeDetectionStrategy.OnPush: Every component must declare changeDetection: ChangeDetectionStrategy.OnPush for fine-grained reactivity and maximum speed.
  • Angular Signals for Reactive State: Use signal() for mutable state, computed() for derived values (never call dirty functions inside HTML templates), and effect() strictly for external side-effects.
  • Angular 22 Control Flow: Exclusively use built-in control flow: @if, @for (track item.id), @switch, and @empty. Legacy *ngIf and *ngFor are forbidden.
  • Functional Dependency Injection: Use inject(ServiceName) as class field initializers instead of bloated constructor injections.
  • Signal Inputs & Outputs: Use input(), input.required(), and output() instead of legacy @Input() and @Output().

2. Standard 2: TypeScript 6 Strict Typing & Clean Engineering

  • Zero any Policy: The any type is 100% prohibited. Always define strict models, interfaces, or type unions (e.g. Country, CountryViewMode, FormStatus). Use unknown with type guards if dynamic.
  • Naming Conventions:
    • Components: PascalCaseComponent (e.g., CountryComponent)
    • Services: PascalCaseService (e.g., TenantService, AuditService)
    • Models / Interfaces: PascalCase (e.g., Country, ExportField)
    • Variables & Functions: camelCase (e.g., isLoading, fetchCountries())
  • RxJS Memory Leak Prevention: All Observables must be piped through takeUntilDestroyed() or converted to Signals. Unmanaged subscriptions causing memory leaks are strictly forbidden.
  • Defensive Error Handling: All asynchronous operations must include try/catch blocks, user toast notifications, and AuditService error logging. Never swallow errors.

3. Standard 3: UI/UX, Multi-Tenant Security & Form Standards

  • Tailwind CSS 4 Design System: Zero inline style="..." attributes. All styling must follow design system utility classes and CSS variables for theme consistency across light/dark and tenant branding.
  • Enterprise Reactive Forms: Use typed Reactive Forms with instant inline validation indicators and disabled states during asynchronous submissions to avoid duplicate actions.
  • Two-Tier Multi-Tenant Security Gatekeeper:
    • Tier 1 (TenantSetting Table): Tenant-wide field enablement. If hidden at tenant level, no user sees it.
    • Tier 2 (UserPermission Table): Granular per-user role visibility.
    • Strict data isolation by tenantId across all API calls and caches.
  • Clean Console & Zero Regressions: Zero TypeScript compiler warnings, zero template errors, and zero runtime console errors allowed.
